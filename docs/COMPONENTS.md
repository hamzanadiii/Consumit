# Shared component roadmap

## Account recovery — workspace, 2026-10-27

`ForgotPasswordScreen` and `ResetPasswordScreen` receive server-validated `nextPath` values and use the shared internal-path validator for recovery navigation. Code entry is available before a new request and receives focus after a successful request. Both screens use synchronous pending guards and disabled fieldsets, retain fields after errors, and provide a return to sign-in. Reset includes 6-digit-code guidance, bounded password input and a 44px visibility control. Successful reset opens sign-in with a non-secret confirmation flag; `SignInScreen` renders its success status while retaining the destination.

The shared auth `FormMessage` exposes success as status and focuses/scrolls new server errors. Auth feedback uses the active theme’s text/danger colors, avoiding fixed pale success colors in light mode. The recovery routes parse their return parameters through `internalNextPath`; client navigation preserves the sanitized query and fragment.

`SignInScreen` and `SignUpScreen` retain the return destination in their account-switching links and unverified-email action. Sign-in locks email and password while login is pending; a failure keeps the entered values and focuses the error before retrying the same destination. `RATE_LIMITED` gets calm sign-in-specific wait guidance instead of generic backoff wording, with the same credentials and destination retained for retry. Other identity forms get calm wait-and-retry guidance for rate-limited requests. Signup username feedback uses one persistent live region with reserved height, preventing blur-triggered button movement. The signup sign-in link exposes a 44px target. `VerifyEmailScreen` receives the same server-validated destination and has one verify/resend action state plus a synchronous pending guard. Resend validates the email independently of the code, preserves failed drafts and clears/refocuses code entry on acceptance. Rejected-code feedback exposes signup restart; successful verification carries the destination into onboarding. Back to sign in remains available while idle.

`SignUpScreen` uses per-step field refs, explicit transition focus and synchronous submit/resend guards. Its identity and verification fieldsets set `min-w-0` so a long unbroken address cannot stretch controls behind the shell's clipped edge. Verification code is controlled: failed requests retain it, accepted resend and pending-registration restoration clear it. The phone-visible email-edit action and the return-to-pending action share the request guards. An accepted registration snapshot restores the email, password, username and display name only in component memory; it is never written to storage or a URL.

## Settings account actions — workspace, 2026-10-29

`SettingsScreen` gives export, password change and account deletion distinct pending, error and success states. Export progress and its focused, visibly outlined retry error stay beside Export your data; successful preparation announces that the browser download is ready in theme-aware text. While an export is pending, sign-out and the other account actions are unavailable, and each phone account action retains a 44px target. Export does not claim that the browser has saved or retained the file; the download helper owns the file response and suggested filename.

The username field describes the 3–30 lowercase-letter, number, and underscore rule and associates any username-change date with the input. Native constraint validation keeps invalid values from reaching the profile API and focuses the field.

The episode-reminder preference keeps the last saved value visible while a write is pending or fails. A failed write focuses the same-choice Retry action with a visible orange ring and a 44px target; retry submits the attempted value, then refreshes the saved preference.

## Profile editor dialogs

`ProfileEditorDialog` honors a visible descendant marked with `data-initial-focus`, then keeps Tab within the panel, returns focus on close, and lets the parent choose backdrop/Escape dismissal policy. The banner editor starts in its catalog search, clears stale results when the query or scope changes, shows no-match copy only after a successful empty response, and preserves the staged banner through search failure. Retry search receives focus with a visible focus ring and a 44px target.

## Public profile archives — local, 2026-10-29

`ProfileSectionNavigation` shows visitor archives only when that section is public. Tags require both Tags and Reviews visibility; Activity stays independently visible but omits review events while Reviews is hidden. Visitor Activity, Watched, Diary and History render safe, read-only archive data from the profile archive endpoint. Public History shows title, episode identity and completion date without playback progress, Watch again or Log to diary actions. Hidden sections stay unavailable when opened directly.

Visitor archive paging retains loaded rows and uses a 44px action. A failed page focuses Try again; successful recovery returns focus to the section heading when the final page exhausts its cursor. Diary and review excerpts wrap long text and cap at six lines. Deterministic 320×720 profile checks cover all four sections, WCAG 2.2 AA, no overflow, review visibility and same-cursor Activity recovery. The full Social browser suite passes 12/12. Screenshots: `.impeccable/review/social/public-activity-320x720.png` and `public-history-320x720.png`.

Public review tag chips open Activity with the selected tag in the URL. The visitor page announces the active filter, limits its rows to matching diary/review tags, and provides a 44px Show all activity link. A no-match result remains explicit, and a 320×720 tag-to-Activity browser flow passes axe WCAG 2.2 AA and no-overflow.

The owner Watchlist keeps saved title records available when catalog poster details fail. `Retry artwork` remains a 44px action; retry refreshes title details without changing the saved records.

## Rules

Account help and recovery links occupy their own wrapping layout space with explicit 44px targets, independent of the 14px interface root. Username checks discard stale responses. Verification and resend actions exclude one another and show bounded loading/error states while retaining entered details. Route failures use neutral app-wide copy, shared ErrorState, a framework retry action, Home navigation, and a safe reference; not-found states offer Search and Home. Root-layout failures render a standalone reload surface without shell/session dependencies.

Native player chrome stays visible while a keyboard-focused control is operated, including playback start and pointer movement. Mouse-only focus does not prevent the normal fade; leaving keyboard focus restores automatic hiding. The browser's `:focus-visible` state distinguishes the two.

Watch source/session changes clear the active caption track through a silent controller reset. The viewer's saved caption-enabled state and language order survive, then match against the new source and discovery results; only an explicit Off choice changes that preference.

Watch's initial unavailable state retains Try again and Return to title and adds a shared Choose another server action. It opens a labeled native Server select with Auto, disabled unavailable choices, loading, retry and empty states. Selection remains busy until resolution ends, survives a failed startup retry, and retains the canonical title/episode and native checkpoint. No session is required to request the configured provider snapshot.

`shared/ProviderFrame` remains the Watch/Admin surface for validated embeds under ADR 0006. In Watch, a compact branded toolbar carries Back to title, exact title/episode, friendly provider attribution, Sources and Episodes above the provider iframe; the frame fills all remaining height. Sources opens the shared `PlayerPanel` in its larger 480px desktop / 440px tall presentation, with 56px server selectors and source choices; it still clamps to the viewport and available space on phones and short-landscape screens. Episodes uses the compact panel. Both open below their trigger, restore trigger focus on close and retain fixed headers with scrollable bodies. Reload and Open in new tab remain secondary; Try another server stays in Sources. Connection status is announced accessibly, while progress-sync and manual-next limits stay quiet but visible. The iframe keeps its own controls, permissions, referrer policy and plain-frame behavior without a sandbox attribute. Consumit does not synthesize progress, decoded playback, completion, quality, Cast, subtitles or auto-next from document loading. Requested anime audio guidance still points inside the frame; provider popup/navigation behavior remains provider/browser owned.

`shared/AdSlot` is no longer mounted by active product screens (2026-10-15). Home, Movies/Series/Anime catalogs, all title details, Watch and the owner's Profile overview omit display banners, their imports, wrappers and reserved layout space. Wide detail layouts omit the former 300px ad column. The unused component implementation remains available in source; it is not an active surface. Profile backdrop artwork and community cards remain product content.

`shared/AdStatus` lives in Settings → Browsing & advertising, reusing `PreferenceRow` and `Toggle` with a visible On / Off / Loading value. FilScreen navigation contains only the Settings destination. Anonymous Settings renders `GuestSettingsScreen` so opting out never requires an account; authenticated Settings retains its existing profile/privacy/playback sections and adds the same advertising control. On is the default. `useAdStatus` fails closed until device and experience preferences load and whenever account preferences cannot load. Same-document and storage events apply Off across tabs immediately; if a browse document already loaded the pop-under script, it reloads to clear its handlers. Failed account sync retains the device choice, focuses a visible orange-ring Retry sync action with a 44px target, and retries the pending account write. Watch never reloads for this choice. `shared/PopunderAd` loads the owner-supplied publisher script on public browse routes, with at most four injections per rolling 30-minute window and at least five minutes between injections per device; Web Locks serialize claims across tabs when available. Settings, Admin, authentication, onboarding and Watch are excluded. The separate display `AdSlot` remains unmounted, so display banners and reserved space stay absent. Ad status controls Consumit browsing ads only and does not exclude provider frames or reject playback attempts; external providers control their own advertising. `adsEnabled` also rides along on playback preference requests.

- Finish one component and its meaningful states before starting the next.
- Add only variants already demanded by an active design or the immediately selected screen.
- Preserve Cinema After Midnight: near-black surfaces, warm editorial type, signal-orange actions, scarce lilac and lime signals, and compact corners.
- Use Lucide for interface icons. Use Radix primitives when keyboard behavior, focus management, or ARIA semantics are complex. Do not import a generic shadcn theme; individual patterns may be adapted into Consumit-owned code when useful.
- Every component ships through `@consumit/ui` with its public types, a catalog example, behavioral tests where interaction exists, and responsive/focus verification.

## Cross-screen contracts
