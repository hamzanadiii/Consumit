## 2026-10-31: VidBolt resolution User-Agent and staged `proxy.vidbolt.xyz`

Two independent upstream blocks govern VidBolt resolution, and a canary separated them. On the resolution host `vidbolt.xyz`, Cloudflare's WAF returns 403 for a request with no `User-Agent` or the literal `node` UA **regardless of egress IP**, while a browser UA returns 200 from residential egress but still 403 from Cloudflare/VPS egress. The adapter had been sending only an `accept` header, so it failed everywhere; it now sends the shared browser `userAgent` on the resolution request. That header fix is necessary but not sufficient: the IP-class block persists on top of it, so VidBolt resolution still requires residential egress (the deferred gateway) and the header fix must ship with it or the gateway alone will not work. WeCollege, NontonFlix and EmbedMaster already send a browser UA, so this defect was VidBolt-specific.

Host evidence across nine titles from residential egress (real adapter, production `node:https` transport, no harness injection) yields live sources only from `img.rousav.tech` (five movies) and `proxy.vidbolt.xyz` (three series); `img.animecurx.tech` and `img1.hscow.com` returned none in this sweep. The roster and `PLAYBACK_RELAY_PROVIDERS` have therefore been staged to add `proxy.vidbolt.xyz` to the VidBolt row, while `img1.hscow.com` stays out for lack of live evidence. This staging widens only the API/resolver host scope; the media-relay Worker's `RELAY_PROVIDERS` was deliberately **not** redeployed this slice (its checked-in deploy maps are empty or stale and would regress production, and the media leg has no effect until egress lands). Production playback is not claimed; the Worker deploy belongs with the deferred egress gateway slice.

On release `rebuild-20261022-vidbolt-relay-v2`, configured production Browser checks passed for Fight Club (TMDB 550, movie) and Breaking Bad S1E1 (TMDB 1396, series): both returned HLS 1080p, confirmed a first frame and a 10-second seek. Measured startup was 7.76s and 14.32s respectively, with one observed stall in each preview. These checks establish playback on the tested Chrome session, not full-episode reliability or Safari/native-HLS compatibility. Production relay Worker version `b189505f-2286-4d53-821f-1d12cab0147e` carries the matching two-host policy. See the [VidBolt relay record](../runbooks/worker-relay-trial.md#vidbolt-prove-production-acceptance).

## 2026-10-15: Admin order replaces delivery-tier and personal ordering

The owner's later instruction makes the saved Admin attempt order per title kind authoritative across Direct, Relay and Embed. Delivery mode selects the configured transport and its independent health/admission checks; it does not rank a provider. Automatic startup, owned attempts, provider listing and legacy fallback follow the same eligible Admin order. Without a saved order, configured priority and registration order apply without delivery-tier sorting. Recovery exclusions remain scoped to delivery and upstream group, so a failed Direct route does not suppress an independently approved Relay route for the same upstream.

Watch removes Manage servers, Move up/down and Reset to default. Manual server selection remains available and keeps title/episode identity and member progress. Existing personal orders may remain in stored preferences and old request contracts for compatibility, but playback ignores them. This supersedes the earlier personal-order amendment and Direct → Relay → Embed ordering statements in this ADR and ADR 0006. Existing source validation, independent Relay approvals, finite recovery and transport ownership remain required. The later plain-frame amendment in ADR 0006 removes provider-frame advertising exclusions. A renewal stays on the selected provider; failure recovery follows Admin order. No production rollout is implied by this workspace decision.

## 2026-10-15: personal server order and finite recovery

The owner explicitly authorized personal Main Server / Backup ordering for movies, series and anime. A saved exact order now overrides Direct → Relay → Embed. Admin order and the existing delivery tiers remain the default and place newly added, unranked providers after saved choices. This amendment supersedes unconditional direct-first ordering statements below; it does not authorize extra spending, new hosts, disabled providers, regional bypasses or automatic Direct-to-Relay conversion.

The owned playback-attempt API freezes eligible labels/order for one recovery cycle, visits each eligible provider once through bounded requests, and returns pending, ready or exhausted with actual progress. Continuation and cancellation use the existing private playback cookie and Valkey namespace. Explicit manual selection ends the old cycle; retries can start a new cycle. Hostile output validation, independent delivery health/admission, source expiry and approved egress remain authoritative. Exhaustion stops automation and offers manual selection or retry. Ads Off excludes external frames requiring an unsandboxed context under ADR 0006. The owner subsequently authorized application release `rebuild-20261015-reliable-v1`; both compatible playback paths now implement this amendment while the separate process retains its 1% canary. [The acceptance/deployment record](../audits/reliable-playback-2026-10-15.md) preserves incomplete device, field and full-promotion evidence.

[ADR 0008](./0008-provider-egress-and-media-routing.md) extends the Worker-only transport decision with an independently signed, bounded OVH media fallback for `lookmovie-relay`. The Direct → explicitly configured Relay → Embed waterfall, hostile source validation and control-only API remain in force. Purstream's reviewed direct HLS recipe declares full-VTT subtitle rendition handling through `hlsSubtitlePlaylistFormat: vtt`. The owned hls.js loader wraps only raw VTT subtitle-playlist responses into a one-segment VOD playlist. It preserves the original URL, rejects unsafe addresses, and bounds document size, cue count and duration; regular HLS subtitle playlists pass through. The browser still fetches caption and video bytes from the configured provider. This is playlist compatibility in the direct engine, with no new relay grant, host policy or API byte route. [ADR 0006](./0006-provider-embed-fallback.md) supersedes provider-embed deferral and the two-tier timeout budget. Direct/Relay ownership and independent Worker approval remain in force.

Watch suppresses the document Referer for owned media requests while retaining the browser Origin and ordinary CORS enforcement. A document response header handles initial navigation; route metadata applies the same policy on client navigation and restores the root policy outside Watch. ProviderFrame retains its explicit iframe referrer policy. Relay session issuance reserves five seconds below the strict thirty-minute capability limit. A live RiveZephyr comparison on 2026-10-04 found that Admin's ninety-second preview grant succeeded while a Watch grant exactly at the maximum was rejected by a slightly slower edge clock. The shorter cutoff is published in both the session and grant; the edge's lifetime, expiry, origin and host validation remains unchanged. This applies to estimated expiry and known long-lived relay sources. See [the RiveZephyr audit](../audits/rivezephyr-watch-2026-10-04.md).

Healthy Watch-page HLS relay renewals preserve the existing engine and buffered movie. A stable internal lease getter exposes the latest same-source/provider/rendition capability to an XHR loader wrapper; it never calls `loadSource`, replaces MediaSource or seeks during a matching renewal. The wrapper resolves original fragment addresses through fresh, bounded VOD control playlists. Complete URI-independent playlist metadata must match, including durations, sequences, discontinuities, rendition/codec attributes, IVs and byte ranges; cached AES-128 key bytes must also match before fresh segments are accepted. New control reads omit credentials, have a twelve-second deadline and finite document/reference/key limits. Grants remain immutable and expire normally. Relay renewal starts sixty seconds early; direct retains fifteen. Changed source identity, incompatible playlists, upstream failures, unsupported/live encryption, native media, native HLS and cast use existing recovery. This decision removes clock-driven visible refreshes for matching MSE HLS recordings; it does not promise immunity to real delivery failures. See [the boundary audit](../audits/proxy-gapless-2026-10-03.md).

Unknown upstream expiry is a freshness estimate, not an authoritative access cutoff. Reviewed relay adapters mark that distinction with internal `expiryEstimated` metadata. Their SDK source still has the five-minute conservative deadline for validation/cache freshness, but member playback issues a relay capability for at most the existing thirty-minute grant window. A known provider expiry or an unmarked source remains authoritative, and direct playback keeps its existing deadline. This removes synthetic five-minute segment denials on healthy proxy playback without extending a real upstream token's validity. Existing issued capabilities retain their original expiry; fresh resolution/renewal adopts the new policy. Normal bounded renewal and failure recovery remain necessary. See [the movie 522406 audit](../audits/proxy-renewal-522406-2026-10-03.md).

On 2026-10-03 the product owner reopened [ADR 0003](./0003-browser-direct-media-only.md) and selected this order: direct providers → distinct relay providers → supported provider embed once added later. Direct providers run in the saved order first; only after that bounded waterfall is exhausted may an approved Worker carry HLS/native media. Relay recovery stays in the relay tier, with independent provider health and exclusions. Consumit keeps its player, title/episode identity, progress and history; the API resolves and issues expiring encrypted capabilities without carrying video bytes. This trades a bounded extra delivery path for potentially lower relay cost while requiring measured startup, buffering, requests and CPU before increasing traffic. The owner selected Workers Free for now; upgrading to Paid is deferred. Free enforces 100,000 requests per account per UTC day and 10 ms CPU per invocation, so quota/CPU exhaustion can make relay unavailable. No paid subscription is activated.

Reusable configuration is disabled by default; the operator-authorized local trial is enabled separately. Existing providers default to deliveryMode: direct, including Vixsrc. Only providers explicitly configured with deliveryMode: relay belong to the relay tier, and API/Worker exact-host policies must separately permit their traffic. A failed direct provider is never automatically converted to relay. The owner subsequently authorized twelve distinct relay rows from PROVE, including relay-only WeCollege Miami and Boise; the active roster and measured limitations are recorded in the trial runbook. 9Anime owns only hd-2; AniWave remains separate. HLS manifests and native media are supported; DASH relay, arbitrary source byte transforms, automatic separate-audio relaying, provider iframe fallback, and P2P are deferred. A fixed, provider/host-scoped BingeBang YMovies manifest recipe decodes its XOR playlists and fetches their .jpg endpoints; native media bytes remain untouched. Its input cap is 1 MiB, with the existing 2,000-reference cap. Zoko has recorded noncredential hints on its one approved split segment host. Healthy relay renewals retain the relay path. With relay enabled, the rolling ten-minute recovery budget covers the eligible direct and relay candidates, capped at 128; without relay the existing three-switch limit remains. Each discovery tier has a twenty-second deadline, the browser allows forty-five seconds, and the gateway allows fifty. Manual selection respects the selected provider's declared delivery tier; choosing a direct provider or starting a new session can return to direct delivery. Exhausting relay currently returns an honest unavailable state; adding a provider embed is a later slice.

Worker capabilities bind a URL, provider, application origin, header hints, expiry and nesting depth. Every playlist reference and redirect must pass the edge allowlist. Credentials, arbitrary caller URLs, wildcard hosts, content steering and playlist variables are rejected. No caching of personalized grants or playlists is enabled. Use only permitted traffic on operator-controlled/approved public domains; attach no private-network bindings. Workers request/CPU pricing is a hypothesis to validate, not a guarantee of accepted traffic or total infrastructure cost. Seven days of measurements precede scaling; optional P2P is a later experiment on popular streams with identical media/renditions that demonstrates net benefit. It supplements successful media delivery rather than serving as a guaranteed final recovery route. See the [trial runbook](../runbooks/worker-relay-trial.md).
