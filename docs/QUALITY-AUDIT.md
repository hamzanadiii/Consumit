# Quality audit — 2026-09-24

This audit covers the web application, Fastify API, contracts, shared UI, provider SDK, Cloudflare media Worker, persistence, and deployment configuration. Findings below are grounded in code or a reproducing check. The fixes in this change address the urgent trust-boundary and broken-gate findings; the remaining items need separate, measured slices.

## Confirmed findings

| Priority | Finding and evidence | Impact | Status |
| --- | --- | --- | --- |
| P0 | `worker/index.ts` fetched a caller-supplied `url` even when `HMAC_SECRET` existed but `token` was absent; playlist rewrites omitted the token. | The Worker could be used as an unsigned public fetch proxy, and nested playback bypassed the intended signature. | Fixed: every media request carries a signed grant, including HLS child playlists, keys, and segments. Worker tests cover missing, altered, expired, and child grants. |
| P0 | The Worker accepted arbitrary `headers`, `origin`, and `referer` query values and followed redirects automatically. | A caller could change upstream request behavior or redirect outside configured media hosts. | Fixed: signed grants contain provider-scoped hosts and headers; all redirects and playlist children are checked before fetch. Upstream documents have byte caps and media streaming has a per-response cap. |
| P1 | Worker rate limits lived in an isolate-local `Map`; `Referer` was treated as embed authorization in `embed-routes.ts`. | Limits diverged between isolates and Referer could be forged or absent on valid public embeds. | Fixed: [Cloudflare's shared rate-limit binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) gates Worker requests, the zone rules cover `/v1/embed/`, and public embeds no longer depend on Referer or the obsolete admin domain list. |
| P1 | The root gate failed on API lint, API type errors, and a health test that inherited ambient playback configuration. Subsequent gate passes exposed provider SDK and web lint errors. | Changes could not be reliably verified. | Fixed in code; verification results are recorded below. The vendored minified signing chunk is explicitly excluded from lint while maintainable SDK code remains checked. |
| P1 | A contracts test omitted the required `role` field from a member fixture, so it asserted a valid response against an invalid object. | The test failed after the API suite passed and obscured the actual contract behavior. | Fixed the fixture; all 14 contracts tests pass. |
| P1 | Integration files each truncate `Member` but the Vitest config allowed files to run concurrently. A run against the isolated test Postgres deadlocked and produced missing-row failures across suites. | Integration results were nondeterministic and could conceal data defects. | Fixed: integration files now run sequentially; six files and 29 tests pass against isolated Postgres and Valkey. |
| P1 | `playback.ts` held recovery locks in a process-local `Map` while multi-instance playback uses shared Valkey. | Two API instances could switch or recover the same session concurrently. | Fixed: playback stores expose atomic, expiring claims with ownership-checked release; recovery and manual switching use the shared claim. |
| P1 | Admin provider overrides used `Boolean(value)` and `Number(value)` coercion. | Strings such as `"false"` enabled a provider setting. | Fixed: administrative patches require actual booleans and bounded integers. |
| P1 | `postgres-member-data.ts` silently caps library reads at 5,000 watched, diary, and saved records and 1,000 lists. | Members beyond those limits receive an incomplete Library with no pagination signal. | Open: design paged Library contracts and queries together with the screen; preserve stored records and ordering. |
| P2 | Provider examples contain broad media host patterns such as `*.workers.dev`; the Worker signs HLS children within a provider's configured host scope. | A broad operator allowlist can permit more upstream destinations than intended. | Open: narrow production provider media hosts to owned hostnames and audit every `mediaHostPatterns` expression before enablement. |
| P2 | `AllowedDomain` remains in the existing Prisma schema and migration after public embed domain controls were removed. | An unused database table remains. | Open: drop it in a reviewed migration after confirming no production data needs retention; no table or member data was deleted here. |
| P2 | `aphrodite-gate.ts` is a vendored minified upstream signing chunk with `@ts-nocheck`. | Source review and automated lint cannot provide the same assurance as for maintained adapters. | Open: pin provenance and checksum, add an isolated contract fixture, and replace the chunk when a supported upstream interface is available. |

## Evidence and measurements

- The API uses exact-Origin mutation checks and opaque Valkey sessions; provider resolution uses a DNS-pinned, bounded HTTP transport and validates output at the adapter seam. These were retained.
- The catalog uses bounded upstream requests and stale caching; the resolver has a deadline, per-provider attempt budgets, source validation, a cache, and a circuit breaker. No unmeasured caching or ranking rewrite was made.
- Before changes, `bun run check` stopped at seven API lint errors. Separately, API type checking found four errors, and one of 282 API tests failed. `bun run infra:validate` stopped because Terraform is unavailable in this environment.
- Worker unit tests pass (five tests); Worker lint and deployable-source type checking pass. The Wrangler deployment dry run passes. API integration tests pass (six files, 29 tests) against the isolated test Postgres and Valkey services. Docker Compose production configuration parses successfully.
- The post-change production build succeeds. The Bun API build emits an 11.18 MB `index.js` and 6.20 MB `import-worker.js`; Wrangler reports a 17.07 KiB Worker upload (5.16 KiB gzip). These are build outputs, not transfer sizes or a before/after performance comparison.
- After fixing the contract fixture and VidNest subtitle parser, the separate root test command passes: API 282, contracts 14, provider SDK 114, shared UI 107, web 201, and Worker 5 tests.
- Final `bun run check` passes end to end: lint, type checks, all unit suites, the API and web builds, and the Wrangler deployment dry run.
- Playback browser tests could not start because an existing Next development server holds the shared `.next/dev` lock. The server was left running; an attempt to start the production build on the playback test port was rejected by the execution policy. `bun run infra:validate` reports the missing Terraform prerequisite. k6 is also absent, and backup restore has not been exercised.
- The existing `tests/playback/load.js` is a controlled-fixture k6 scenario. Production latency, browser bundle cost, database query plans, provider success rates, and restore time remain unmeasured here; no performance or availability target is claimed as achieved.

## Remaining verification

Rerun the browser suite after the existing Next server releases its development lock, and run Terraform validation, k6, and a backup restore when those prerequisites are available. Before deploying the new proxy grant format, follow the coordinated Worker and API rollout in the Cloudflare runbook; old proxy URLs are intentionally incompatible.
