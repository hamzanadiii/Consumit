## Recovery and operation

- Queue age, terminal rows, queue readiness, pool waiters, event-loop lag and provider playback failures have Prometheus alerts. Test actual alert receipt before promotion.
- To retry a reviewed failed outbox UUID, run `node retry.js UUID` in the general worker image. Replay removes the old failed queue job and resets only its failed PostgreSQL row. Domain operations must remain idempotent.
- After queue loss, the dispatcher recreates unfinished jobs and missing recurring schedules; the browser worker separately reconciles its check schedule. Successful PostgreSQL rows are not replayed. Restore drills must separately prove member/database recovery with existing off-host backups.
- General shutdown drains jobs before closing Redis, PostgreSQL and telemetry; Compose permits 180 seconds. Playback has an 80-second grace period; the browser worker has 120 seconds. A forced crash relies on expiring leases and BullMQ stalled-job recovery.
- Stop consumers before PostgreSQL, Valkey and the collector. Retain explicit Compose dependencies for the combined rollback and browser worker. Idle database connection errors are redacted and handled; a collector shutdown failure is reported without failing member/database shutdown. Application, worker and collector container logs rotate at 10 MB with three files each.
- W3C trace context crosses internal calls. The rebuild collector writes sampled OTLP JSON to rotating 10 MB files, keeping three backups and one-day age retention. This is bounded incident evidence, not an analytics service or searchable trace backend. The file exporter is alpha; validate the pinned collector before rollout. [Collector documentation](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.161.0/exporter/fileexporter).
- Browser error reports contain fixed page/category/name labels only, at most ten per minute; no exception messages, stack, member identity, source URLs or cookies. Member responses remain private/no-store. Public title caching stays intact.

## Storage across hosts

Disk is the initial subtitle backend. Apply `compose.subtitles-s3.yaml` only after configuring a private S3-compatible bucket, region, exact HTTPS endpoint if needed, and a dedicated credential file with read/write permission restricted to the subtitle prefix. SDK retries and object reads are bounded; expiry metadata retains the existing file TTL. Configure an object lifecycle rule to remove the subtitle prefix after seven days; reads reject expired files, but metadata alone does not delete remote objects. Browser URLs stay first-party. Copy/verify still-valid disk captions before switching; otherwise cached captions may need rediscovery. Budget and restore checks precede cross-host activation.

## Acceptance and measurement

Automated fixtures: PostgreSQL integration, pinned queue compatibility, queue unavailable at startup, duplicate delivery, killed worker/lease expiry, exhausted retries, queue loss/reconstruction, malformed output/config disable switches, browser decode/resume and private gateway routing. `tests/rebuild` runs product and playback as independent Node processes with controlled media. Touch emulation is not a physical Android check. Existing playback suites retain quality/audio/subtitle/fallback/Embed/casting fixtures.

When reusing image servers for the browser fixture, seed the fictional account through `node --import ./apps/api/node_modules/tsx/dist/loader.mjs tests/rebuild/seed.mts` with the dedicated localhost test `DATABASE_URL` and `DATABASE_SSL_MODE=disable`. The seed refuses non-local or non-test databases and changes only its fictional account. Database integration suites can remove fixture members, so seed after those suites and before the browser run. Source fixture startup seeds automatically.

Physical Android and Safari/iOS: record model and OS/browser version, title kind/exact episode/provider/route, guest and member resume, seek/refresh/fallback, quality/audio/captions, portrait/fullscreen exit, network change, and supported casting. Record honest Embed restrictions: external controls and no supported progress synchronization. Run on the candidate cohort after baseline checks; retain failures by provider.

Load tests must count delivered successful requests, rate limits and failures separately. API reads p95 ≤250 ms; warm search p95 ≤200 ms; LCP p75 ≤2.5 s; INP p75 ≤200 ms; CLS p75 ≤0.1; eligible playback starts ≥98%; first frame p75 ≤3 s/p95 ≤8 s. Browser dev builds and one synthetic watch do not establish field percentiles. Count unavailable/ineligible providers separately and declare the denominator before measuring start success.

Before full traffic promotion, record measured host headroom and the total recurring invoice cost within 250 MAD, including backup storage and any relay charges. Forecast 100,000 daily active members, four million ordinary requests/day, 20,000 one-hour watches/day, roughly 500 peak ordinary RPS and 5,000 simultaneous watches; keep progress traffic separate. Replace these assumptions with observed behavior. Scaling hosts, database availability, remote storage and paid delivery require a separately priced stage.
