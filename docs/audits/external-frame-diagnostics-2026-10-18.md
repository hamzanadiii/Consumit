# External-player diagnostic boundary — 2026-10-18

VidRift's reviewed protocol now supports optional read-only reports in Watch. No report enters native playback events or writes member progress. Vixsrc remains unsupported because its nested-frame forwarding has not been verified; AniList binding is also unsupported.

Evidence `ev_0e2efa2e966407da3c1d701a54ffde5acfdf7d6c919b5ab589e2871170dd94a6` observed immediate-parent `vidrift:unpaused` and advancing `vidrift:progress` messages. The observed movie ID is a decimal string; season, episode and AniList are null. The adapter admits this exact representation. Identity-free UI/provider-list messages were observed but are deliberately ignored. Chrome terminated its owned process. [Sanitized evidence](./external-frame-diagnostics-2026-10-18.json) retains only bounded identity/status observations, not provider stream URLs, credentials, ad content or free-form reasons.

The bridge requires the reviewed provider, HTTPS origin and canonical source path before parsing. It rejects unrelated/nested frame windows, wrong IDs/episodes, unsupported anime, strings, unexpected keys, oversized reason fields, nonfinite/out-of-range positions, progress beyond duration and regressing progress samples. Its receive clock is monotonic, accepted events are separated by at least 500 ms and capped at twenty per minute. These conservative diagnostic drops never alter media or seeking. Reload/source changes invalidate listeners and pending batches.

The dedicated route enforces the existing playback-owner cookie and origin policy, a strict 4 KiB body, twenty-event batches, a thirty-request-per-minute route budget and a shared-store five-second batch cap. It validates the current VidRift iframe session and source before recording the separate low-cardinality `playback.frame.reported` counter. It stores no history or reported media position. Failed delivery is discarded without retries.

Acceptance: browser tests cover hostile origins/windows/payloads, exact movie/series identity, unsupported anime/providers, floods, regressing samples, reload invalidation and bounded queue teardown. API tests cover ownership, native-source rejection, stale source IDs, strict/redacted schemas, origin/cookie protection, shared-store throttling, separate metrics and the absence of native event/viewing or session persistence writes. Availability of the provider protocol across every title, episode and browser is unproven; missing reports remain missing data.
