# LookMovie: one server with working movie qualities

The member job is choosing LookMovie once and changing its available resolution through the existing Quality panel. PROVE's adapter and Consumit's adapter use the same LMScript movie search/view protocol, but PROVE names its returned sources by quality. Consumit now declares one `lookmovie` quality group so those fixed renditions become choices within the existing server. TV remains unsupported, consistent with PROVE's movie-only capability.

The original live repro for movie 550 returned three valid-looking upstream candidates but zero validated Consumit sources. All candidates used `srv315.excentionses.cyou`; the configured rules only covered the older `faitioninthrey.site` and `superoled.site` domains. Native fetch also returned those three candidates, and the first playlist and complete media segment returned 200 with CORS `*`. This rules out an upstream document or media outage for that sample. The shipped example and local configuration now additionally admit only numbered `srv` subdomains of `excentionses.cyou`. Unrelated domains, bare roots and lookalike suffixes remain rejected.

The running API also rejected manual selection with 400 because its durable LookMovie override was `removed: true, enabled: false`. The requested repair restored this row as enabled Direct video through the existing revisioned store, writing its audit entry and retaining the saved movie order. No other provider override changed.

Regression checks failed before the fix on the missing quality group and rejected current CDN. They now cover one roster entry, only heights exposed as alternate-quality metadata, same-session switching among 1080p/720p/480p, and hostile host rejection. Fifty-seven adapter/configured-provider/resolver/delivery checks and 38 Watch tests pass, including retained position/play intent and failed quality selection preserving the current stream. SDK and full API type checking and changed-code lint pass.

After restarting the source-mounted API, the original repro validates three sources and manual switching returns 200. Movies 550 (Fight Club) and 27205 (Inception) each return all three quality choices. For all six quality/title combinations the manifest and first complete media segment return HTTP 200 with CORS `*`. The 550 segments contain 3,122,680 / 1,537,464 / 848,632 bytes at the labelled 1080p / 720p / 480p qualities; the 27205 segments contain 2,842,936 / 1,805,176 / 950,904 bytes.

Desktop Chrome drives the existing optimized Watch page with live guest API sessions and real direct media. The Server panel contains exactly one LookMovie row; Quality contains 1080p, 720p and 480p. Switching from 1080p to 720p retains a paused position of 42 seconds, then resumes playback and decodes 50 frames at 1282×534 (the upstream's 720p-labelled widescreen recording). The first attempt incorrectly asserted a CDN hostname from hls.js's blob `currentSrc`; a later assertion incorrectly assumed a 1280-pixel display width. Corrected checks use the real API provider/quality response and decoded media dimensions. Neither mismatch was a product playback failure. The inspected panel captures preserve the current player design.

API readiness returns 200 and API/web containers are healthy. Web code did not change; the existing deployed player already handles fixed quality groups. These samples verify initial delivery and one retained-position browser switch, not full-title playback, all catalog entries, every region, or Safari. The configured host policy continues to fail closed if the upstream moves to another unreviewed domain.
