The member clarified that the viewport fallback was insufficient: fullscreen must remove Safari's browser bar and keep the selected subtitle visible. This supersedes the iOS path in the earlier viewport repair.

Container fullscreen remains preferred where supported. Otherwise an available Apple video fullscreen API is called after preparing the selected external caption file as a default showing TextTrack. `native-fullscreen-captions.ts` applies cached parsed cues with the existing sync offset, escapes plaintext for WebVTT, disables other files, reapplies cues after the browser's original file load, and follows track replacement. Both media controllers retain showing mode during native fullscreen. Native-mode CSS removes the global native-caption suppression and hides the duplicate Consumit DOM overlay. Exit restores hidden external tracks and the styled inline overlay. Off disables captions. A rejected native request leaves playback inline with retry guidance instead of substituting viewport expansion.

Apple documents [`webkitEnterFullscreen` and `webkitExitFullscreen`](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) for video fullscreen. WebKit's [text-track explanation](https://github.com/WebKit/explainers/blob/main/texttracks/README.md) describes why DOM caption renderers cannot participate in some native fullscreen surfaces. This implementation uses the existing native VTT/TextTrack path, not the proposed new cue-fragment API. iOS owns native controls and caption appearance; Consumit retains the subtitle content, file choice, sync preference and inline appearance settings. In-band captions retain engine timing.
