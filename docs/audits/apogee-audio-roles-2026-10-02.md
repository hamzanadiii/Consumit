# Provider roles and Apogee audio evidence — 2026-10-02

The implementation slice assigns Admin roles and retains resolution/audio-language intent through source recovery. Audio-only registrations are reserved for future separate audio work and excluded from main playback, cached video winners, manual switches, video order, video probes, health, and diagnostic tests. Existing registrations default to Video source. Role overrides retain the existing Postgres revision, actor, before/after audit, and reset behavior. No media relay, paid dependency, or new playback surface was introduced.

Both player cores retain a resolution height independent of engine rendition identifiers. Replacements select that resolution when offered; otherwise a known lower rendition is selected with explicit feedback while the original preference survives. Unknown native resolutions stay unknown. Audio matches canonical language, including ISO aliases, and Watch/public embed recovery carries the latest semantic intent. Anime's explicit SUB/DUB request still controls recovery. Member progress remains independent of media sources.

The bounded configured-adapter inspection sampled Swapped (TMDB 1007757) and Reacher S1E1 (TMDB 108978). The master playlists declared 32 and 29 audio renditions respectively, each with a separate URI accepted by the existing configured media allowlist. Swapped advertised one 1080p video variant; Reacher advertised 1080p and 720p variants sharing the audio group. This is title-specific evidence, not a universal Apogee capability guarantee.

English and Arabic audio playlists returned HTTP 200 with wildcard CORS. A 64 KiB range of each sampled media resource returned HTTP 206 with wildcard CORS. Container marker inspection did not identify an MP4 audio handler or ADTS prefix in those samples; it does not establish demuxed audio codec or browser decoding. No entire segment, full recording, or unrelated-provider pair was decoded in this check. Seeking, synchronization, cut identity, timestamps, discontinuities, sustained audio delivery, and combined failure recovery remain unproven. Admin therefore reports provider-wide separate audio as unverified and audio health as untested; roles cannot promote those facts.

The first inspection incorrectly treated the manifest parser's attribute tuples as a record and missed the audio tags. The corrected run converts them with `Object.fromEntries`; the JSON evidence contains the corrected results only. The initial finding was corrected in the member-facing update.

The next audio experiment should use one exact recording pair and validated separate audio, with bounded drift measurements across play, pause, seeking, and failure. HLS variant alignment requirements are described in [RFC 8216, section 6.2.4](https://www.rfc-editor.org/rfc/rfc8216.html#section-6.2.4); existing in-stream audio selection uses [hls.js audio tracks](https://hlsjs.video-dev.org/api-docs/hls.js.hls.audiotracks). No cross-provider mixer is enabled by this slice.

Sanitized manifest and HTTP observations live in the companion JSON. It excludes media URLs, signed parameters, member sessions, raw upstream payloads, and audio bytes.
