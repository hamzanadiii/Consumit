# Previous Consumit proxy streaming regression

The owner identifies Consumit's previous proxy implementation as the working reference. Git commit `d7c9f4ab24fa701f140b5d27a89b9dc56baa95b9` contains that signed Cloudflare Worker in `worker/index.ts`, named `consumit-proxy`. Thus a migration away from Cloudflare is not an established requirement. The earlier local-versus-edge comparison did not compare that previous implementation and must not be used to dismiss a regression in the replacement relay.

## Comparison and reproduction

The previous Worker signs HMAC grants, sends Chrome 124 User-Agent, Accept `*/*`, a recorded-or-destination Referer and optional Origin, sniffs some extensionless playlists, and copies media with a simple bounded reader. The replacement uses encrypted grants, independent exact-host policies and original-host header scope, but added a JavaScript promise and idle timer for every streamed chunk.

Using the same fresh movie 550 source, Zephyr roots returned 200 through the current edge under both current and previous request headers. Nebula roots returned edge 502 under both header sets, while both returned local 200. These probes rule out simply substituting the old User-Agent/Accept/Referer as a complete Nebula fix. The previous Worker's guessed public hostname returned health 404; it was not assumed to be an available old deployment.

The media repro drives the shipped Admin Browser check and actual Consumit Player. Because fresh API inspection sometimes returns `empty`, its inspection response was replaced only in an isolated browser context with a freshly resolved SDK Zephyr source on the exact approved `zcdn.bluevelvet.space` host and a current encrypted capability. All media requests used the live Worker, without mocked, prefix-only or locally fulfilled media. This test isolates relay/player behavior and does not establish that intermittent API resolution is fixed.

Before the streaming change, playback decoded 4K, sought to 90 seconds at about 15 seconds wall time, then media requests began failing around 30 seconds. The player stopped with `Browser failure: cors` before the normal 60-second preview stop. [Before evidence](./previous-proxy-streaming-before-2026-10-03.json) records network failures and partial-size responses. The owner's screenshot reported `media`; the exact fatal decoder detail in that screenshot remains unidentified. The repro establishes the early delivery stop, not equivalence of those two error labels or a correlated CPU profile.

## Change and validation

HLS assets (`kind: auto`) now pipe through workerd's native `IdentityTransformStream`, avoiding per-chunk JavaScript promises/timers. Known content lengths use native `FixedLengthStream`, which rejects incomplete or oversized output. Each native asset transfer has a 60-second total deadline and request cancellation propagates. Whole native-video sources and sniff-verified Storm/Zeta TS retain their existing idle-bounded streaming path. Authentication, provider order, independent host checks, header scope, manifest decoding and grant expiry are unchanged. This is a streaming correction, not a restoration of the old wildcard policy, four-hour grants or broad content-type coercion.

At deployment `3ba1849b-de28-4d65-818d-30eb3c9c6bdd`, the repeated 55-second run passed with no failed requests, confirmed seeking and continued 4K decoding. [After evidence](./previous-proxy-streaming-after-2026-10-03.json) records that run. The same native streaming change also passed a three-minute soak: 4322 decoded frames, final media position 253.86 seconds after seeking, no failed requests and one observed stall. [Soak evidence](./previous-proxy-streaming-soak-2026-10-03.json) records it. For this isolated soak only, the Admin stop was extended to four minutes and the issued capability to the lesser of four minutes or source expiry minus five seconds; normal product limits were not changed. Some response bodies became unreadable during adaptive switching/seeking; these alone were not classified as relay errors.

The later fixed-length guard is covered by a failing-before/passing-after truncated-body test. Thirty Worker tests pass, including native transfer deadlines, ranges, abort propagation and accurate completion accounting; type checking, lint and build pass. Native transfer logs set `bytesKnown: true` only for completed, enforced content-length transfers; incomplete and unknown-length native transfers report zero with `bytesKnown: false`. These zeroes must not be interpreted as measured zero bandwidth. Sampled log bytes remain insufficient for billing/capacity conclusions.

The final guard was deployed as `a83d8d0d-9b80-46e1-b959-25b3ede7c881`. A further 55-second actual-player check on that version decoded 1312 frames, sought successfully and continued at 3840×2160 with no failed requests or fatal player error; [final evidence](./previous-proxy-streaming-final-2026-10-03.json) records the run. Temporary diagnostics and their expiring authentication sessions were removed after retaining sanitized evidence.

The active plan remains Free and no additional relay server is activated. Three minutes is evidence against the reproduced under-minute failure, not a full-title reliability claim. Nebula's root 502, previously recorded BingeBang/Zeta edge failures, long-playlist CPU risks and intermittent source resolution are separate open issues. Optional embed/P2P work remains deferred.
