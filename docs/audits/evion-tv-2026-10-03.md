# Evion TV integration

The named job is playing TV episodes through Evion TV while using Apogee only for optional audio. The adapter ports the exact TV endpoint from the local PROVE `providers/evion/evion.ts`; it does not import PROVE's framework, registry, or proxy path.

Evion accepts series only. Movie and anime references return empty before HTTP work. Sources, redirected media, nested HLS references (including audio and captions), and a bounded segment prefix must stay on the approved `img.animecurx.tech` CDN. Playback receives direct HTTPS media without provider Origin or Referer headers. The DNS-pinned Consumit transport owns network access. Evion and Apogee share an upstream group; progress and history keep their existing title/episode identity.

On 2026-10-03, the adapter resolved Game of Thrones (1399) S1E1 in 1,600 ms and Reacher (108978) S1E1 in 1,587 ms, each advertising 1080p. Chrome loaded both through the compiled Consumit Watch screen at `http://localhost:8080`. The harness supplied the new adapter's real validated resolution to Watch; CDN requests were live and were not intercepted. Both decoded at 1920×1080, advanced during playback, and resumed after a seek to 60 seconds. The screenshots show different title content. No page errors or failed CDN requests were recorded. These sampled results do not establish speed or availability for every episode, nor a direct latency comparison with Apogee.

The local Evion row is enabled; the committed example remains disabled for explicit operator activation. The single Apogee row is Audio source for movie and series, and the duplicate `riveapogee-audio` configuration row is removed. Saved local Admin overrides enable Evion as Video source and Apogee as Audio source, preserving other provider settings and existing order. Changes pass through the durable provider configuration store with before/after audit records and revision propagation. Combined Rivestream video attempts no longer include Apogee.

130 SDK adapter tests and 47 configured-provider/resolver/separate-audio API tests pass, alongside SDK type checking and targeted lint. Coverage includes exact episode requests, movie/anime exclusion, malformed/unsafe/missing/blocked delivery, direct playlist inspection, and keeping Apogee out of video rosters while preserving audio eligibility. No player or progress contract changes are needed. Companion JSON contains sanitized browser measurements; signed media URLs and raw provider payloads remain outside committed evidence.
