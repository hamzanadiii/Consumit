# PROVE provider additions — 2026-10-02

Status update: CineJoy was subsequently removed from the active local and example rosters at the member's request. The additions and compatibility checks below are historical; see the [Apogee buffering follow-up](./apogee-buffering-2026-10-02.md) for the current roster and player behavior.

The member job is watching through the existing Consumit Player with additional browser-direct providers. The local roster now includes Rive Apogee and CineJoy Lisbon for movies/series. The committed example keeps both disabled until an operator activates them. Existing provider order and account records are preserved.

After restarting the API, the running gateway returned both additions in its movie provider list. Following the series correction below, it also returned both in its series list. Guest-session switches through the first-party API selected `cinejoylisbon` and `riveapogee`, respectively, and both decoded direct first frames from `http://localhost:8080`. API readiness returned 200 and API/web health checks passed.

The primary implementation references are `../PROVE/providers/riveapogee/riveapogee.ts`, `../PROVE/providers/rive/client.ts`, `../PROVE/providers/cinejoylisbon/cinejoylisbon.ts`, `../PROVE/providers/cinejoy/cinejoy.ts`, and `../PROVE/providers/wecollege/wecollege.ts`. Rive’s [first-party docs](https://www.rivestream.app/embed/docs) describe its TMDB-keyed movie/episode API, but direct compatibility was established with browser checks, not the embed documentation.

Apogee’s initial movie-only restriction came from an outdated capability label in the PROVE reference. Live episode queries for series 1399, 1396, and 60625 S1E1 returned sources on `img.animecurx.tech`; series 95396 S1E1 returned no source. The adapter now accepts exact series episodes, and configuration explicitly approves that series CDN alongside the movie CDN `img.rousav.tech`. Series 1399 S1E1 passed a browser first-frame check and a first-party API switch after restart. The 15 provider configuration tests passed, including exact season/episode forwarding, and lint passed. This establishes series support without implying every title is available.

CineJoy’s upstream control protocol was reimplemented with native crypto. A deterministic request vector was captured in an isolated browser with all network requests blocked; the adapter reproduces that vector without downloading or executing WASM. Authenticated-response, tamper, size-limit, exact-episode, unapproved-host, segment-failure, and cancellation tests cover its seam. Media remains browser-direct. Current finite VOD playlists passed duration/seek checks without introducing a player-specific playlist patch.

All 160 provider SDK tests and 26 focused API playback tests passed, as did provider SDK type checking, type checking of the changed API playback slice, and lint on the changed code. API-wide type checking still reports existing failures from the earlier social-contract removal (identity/member-data exports, implementations, and tests); those are outside this provider slice. Sanitized browser evidence is in [the JSON record](./provider-additions-2026-10-02.json). No signed media URLs, member sessions, credentials, or raw control responses are stored in the report.
