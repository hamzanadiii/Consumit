# Consumit release hardening — 2026-10-07

## Scope

Member jobs: safely authenticate and recover an account; browse without exposing private data; discover subtitles and recover playback without losing canonical progress. Operator job: build and assess a release with meaningful configuration, readiness, and smoke checks.

Reviewed the active web/API boundaries, authentication and member authorization, provider/relay transports, subtitle discovery, shared contracts/components, dependency graph, CI, Compose, and deployment runbooks. Existing tests exercise catalog, identity, member data, providers, native playback, and edge delivery. This is a bounded release review, not a claim that every possible defect is eliminated.

The working tree already contained import/social retirement and settings/legal/UI work. Those changes and stored historical data were preserved. Legacy/canary player code, public-embed placeholders, and referenced assets were retained when deletion would alter an active decision or compatibility boundary.

## Fixes

| Area | Problem and resulting behavior |
| --- | --- |
| Rate-limit identity | Arbitrary cookies could create fresh budgets. Only verified sessions use member identity; malformed, expired, and wrong-environment cookies use normalized IP budgets. Credential routes normalize IPv6 to /64. |
| Production request budgets | Per-process budgets reset on restart and split across instances. Production uses shared Valkey counters, finite command deadlines, reconnects, and fail-closed errors. |
| Authentication reads | Rate limiting and route authorization could duplicate session reads. A request-local WeakMap shares the lookup while rechecking every new request, preserving revocation. |
| Origins and deployment mode | Production Compose inherited development defaults. The production overlay now forces production mode and verified database TLS; origins must be credential-free HTTP(S) origins and production origins must use HTTPS. |
| Database TLS precedence | The actual pg parser could replace pool TLS policy with URL settings, including disabling encryption or certificate verification. The client now validates the Postgres URL and removes its TLS overrides before pg parses it; application mode and configured CA remain authoritative. Five regressions reproduce the old behavior and pass after correction, including certificate paths and credential-safe malformed-URL errors. |
| Production backup | The overlay ignored the API's external database URL and inherited the local cron command, restart policy, mounts, and Postgres image tag. It now selects the same database, builds a dedicated Restic image with PostgreSQL 18 tools, verifies TLS with system roots, and runs once under the timer. Infrastructure validation checks the evaluated Compose configuration without logging credentials. |
| Private/error caching | Member subtitle preferences and API errors lacked an explicit private cache policy. Both now use private, no-store. Oversized and unsupported bodies retain accurate 413/415 responses with safe error envelopes. |
| Gateway body boundary | Both gateways still allowed the retired importer's 26 MiB payloads. A shared policy now enforces the API's 1 MiB bound before upstream work and returns private JSON with a matching request reference. Both built-image configurations and an actual oversized HTTP request are verified. |
| Web headers | Documents gain nosniff, referrer/permissions policies, and scoped CSP restrictions for base URLs, objects, framing, and form targets. Public title ISR remains compatible. This CSP does not supply a script allowlist. |
| Streaming teardown | Cancelling a compressed control response could leave its upstream socket open. Pipeline teardown now couples the decoder and upstream. |
| Subtitle discovery | Shared bounded contracts replace duplicated public types. Fragmented/final NDJSON lines work; invalid counts/URLs, oversized bodies, inconsistent IDs, missing completion, and deadlines fail clearly and release readers. Disconnecting cancels provider work. |
| Account UX | Help/recovery links no longer overlap their text and use explicit 44px targets. Older username responses cannot label a new name. Verification/resend requests exclude one another, clear old messages, and recover after failure. Password creation is bounded to 128 characters. Retired Circle promises are removed from touched account copy. |
| Page errors | Shared ErrorState uses the installed Next framework retry callback and Home navigation. Root-layout failures have an independent reload surface. Exceptions remain out of UI; only correlation references are shown. |
| Dead code | Removed confirmed unused identity/anime browser/server wrappers, a catalog map, a re-export bundle, and unused Radix dependencies. Temporary scripts/captures and Terraform state/configuration are excluded from source images and lint inputs without deleting local files. |
| Build dependencies | Docker shares manifest-copy setup and installs dependencies for each application instead of including API/Prisma tooling in the web build. Full development source remains available. Downloads have bounded concurrency; web declares its compiler and Node types directly. |
| Local Docker update | The playback overlay reset Prometheus's profile but omitted its Alertmanager dependency, blocking Compose updates without an explicit profile. Both now activate together, and infrastructure validation checks that invocation. The gateway configuration's new request-limit include initially reached the running old image before the include was installed; rebuilding and recreating the gateway fixes the resulting restart loop. |
| Readiness and smoke | Readiness probes mounted Postgres/request-limit dependencies with a two-second bound, single-flight work, and a one-second cache; liveness remains independent. Smoke checks use the active private route, require anonymous rejection, validate catalog/playback output, support Relay/Embed contracts, and bound requests. CI selects Node 24 and installs the branded Chrome channel used by its playback tests. |

## Dependency findings

Root overrides pin corrected versions for [sharp](https://github.com/advisories/GHSA-wq5f-xc86-pv6w), [source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q), [deepmerge-ts](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), and [mysql2](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3). The lockfile was regenerated and the application checks cover compatibility.

The final advisory refresh also identified six Next.js findings. Next and its lint configuration are pinned to patched 16.3.8, covering [image-optimizer SSRF](https://github.com/advisories/GHSA-cjq9-62q9-8jv4), [cross-user ISR/SSG cache poisoning](https://github.com/advisories/GHSA-mcj8-r9mp-w47p), [self-hosted ISR/SSG cache poisoning](https://github.com/advisories/GHSA-4jqv-mc3x-m676), and the metadata, Draft Mode, and development MCP disclosures returned by the audit. All 409 web checks, web lint/type checks, and the production web image were rerun successfully after the patch.

`bun audit --production --json` returns no findings. The full audit retains one high-severity [braces stack-exhaustion advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), with no patched version listed. `bun why braces` traces it through micromatch/fast-glob to Next's ESLint plugin, a development dependency. No member/provider-controlled pattern is routed to this lint path. Do not treat the full audit as clean, suppress future advisories, or pass hostile patterns to build/lint tooling. Runtime API images contain the bundled application, and the web image uses Next's traced standalone output.

Subsequent checks ran sequentially against isolated fixtures or the updated local app.

- Workspace behavior suites: API 457, contracts 19, relay 47, provider SDK 217, shared UI 196, and web 409 passed.
