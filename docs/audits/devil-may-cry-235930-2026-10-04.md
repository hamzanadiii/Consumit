# Devil May Cry Series playback diagnosis

Later on 2026-10-04, the owner's requested provider additions establish real playback and seeking for this episode through Citadel, Rigel, Vidnest and StigStream. See [the subsequent integration audit](./provider-embed-additions-2026-10-04.md). The diagnosis below records the earlier roster and retains the canonical Series identity finding.

The reported Watch destination is `/watch/series/235930?season=1&episode=1`, the 2025 title and its episode Inferno. The canonical Series detail reports eight season-one episodes. The Anime search returns AniList 1726, the different 2007 adaptation. Changing the title kind or reusing TMDB 235930 as an AniList ID would not establish matching playback and could play another title. Catalog identity and member records remain unchanged.

The actual resolve loop, `node .cache/devil-may-cry-resolve.mjs`, reproduces HTTP 503 `PLAYBACK_UNAVAILABLE` / No compatible playback source in 3.7 seconds. The saved enabled Series roster is Vixsrc, Evion, WeCollege Miami, RiveZephyr and Storm Boron. An independent read of saved provider settings and direct adapter probes distinguishes upstream outcomes from resolver circuit filtering:

- Vixsrc returns upstream 404 for this exact episode.
- Evion returns no sources or an upstream 502 across the two checks.
- RiveZephyr returns an empty source result.
- WeCollege Miami's source endpoint returns an upstream 500.
- Storm Boron returns a candidate but media discovery fails as malformed or times out. Its later circuit cooldown follows those failed validations; it does not establish a healthy stream being wrongly suppressed.

Game of Thrones S1E1 resolves HTTP 200 through Vixsrc as a control, so the Series path is operational. Probes do not change saved configuration or clear circuits.

Two existing disabled Series providers were investigated in isolation. Aphrodite returns a decodable 1080p clip, but visual inspection shows atlantic.st's error-code-4 placeholder rather than the episode. Decoded frames alone are therefore rejected as success evidence. CastleTV first returns an unconfigured `img1.flcwuk.com` destination (rejected normally); subsequent reads return the configured `img1.hlnom.com` host and one valid source. No new host or broad wildcard is allowed.

A memory-only CastleTV playback session, supplied to the deployed Consumit Player via a browser request interception, plays the actual episode at 1280×720. Evidence records 215 decoded frames, playback beyond eight seconds, a duration of 1800.125 seconds, no media failures or fallback, and a successful seek to sixty seconds; the capture was visually inspected. This is an isolated sample, not a full-episode endurance guarantee. The browser intercepts progress/event writes and does not alter member data or enable a provider.

CastleTV remains disabled in the durable Admin override. Making it available in normal Watch would require enabling that existing provider; it would remain a Series source, without catalog reclassification. No production behavior or provider setting is changed by this diagnosis. Signed session artifacts are removed after verification; retained evidence contains only redacted outcomes.
