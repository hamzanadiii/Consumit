# Apogee buffering and CineJoy removal — 2026-10-02

Follow-up: progressive decoding below describes the first deployment. It was subsequently rolled back after the member reported unhandled FetchLoader cancellation errors. The 60-second reserve and seek watchdog remain. Poster CORS, manual-selection fallback ordering, and pending-seek retention were repaired in the [playback error follow-up](./playback-poster-cancellation-2026-10-02.md). The historical measurements below are preserved as evidence of that earlier deployment.

The member job is watching movies and exact series episodes with fewer freezes through the existing desktop Consumit Player. CineJoy Lisbon was removed from the local and example provider rosters; its adapter remains available but is not registered by those rosters. Restarted API lists confirmed it is absent. Member records and media delivery remain unchanged.

The temporary command `bun tmp/apogee-buffering.ts --swapped` reproduced the reported Swapped movie (TMDB 1007757) using the actual shared media engine, the running API, and the Consumit origin. At 20 seconds it had advanced only 14.96 seconds; the 120-second seek did not resume within 12 seconds. Several direct movie CDN requests took 4.9–7.9 seconds. The stream provided only a 1080p rendition. An initial first frame was therefore insufficient evidence of comfortable playback. Temporary harnesses were removed after verification; the controller and coordinator regression tests retain the deterministic failure scenarios.

The smallest deterministic regression is a playing seek whose element remains `seeking` while waiting for bytes. Both controllers previously ignored that state; the legacy controller also cleared its watchdog on `seeking`. New tests reproduced the missing timeout in both cores. A coordinator regression separately showed the extra same-provider refresh before fallback after a delivery timeout. All three failed before their fixes.

HLS now decodes streaming fragment bytes progressively, while keeping credential-free browser-direct fetches. The forward-buffer target is 60 seconds with the existing byte cap and quality limits. Startup does not wait for this buffer to fill. A playing seek starts or resets the existing bounded stall watchdog; paused seeks are left alone and resumed playback clears it. After engine recovery is exhausted, delivery timeouts skip lease renewal and request a direct fallback, retaining position and play intent.

A controlled comparison streamed existing local MPEG-TS fixture bytes at a fixed pace. Disabling progressive decoding in the same engine produced a 2,977 ms first frame after the response completed; progressive decoding produced a 532 ms first frame before the response completed. Both decoded the expected 640-pixel fixture. This isolates progressive loading from CDN cache warming.

The updated engine's live Swapped check decoded in 539 ms, advanced 19.38 seconds in the 20-second observation, held 56.91 seconds ahead, and resumed a 120-second seek in 2.56 seconds. Slow CDN responses still occurred. These short checks establish the measured improvement and recovery behavior; they do not guarantee full-movie reliability or make Apogee's CDN faster. No relay, transcoding service, paid tool, or new player dependency was added.

The optimized web image was rebuilt and recreated; API and web are healthy. The deployed Watch page decoded Swapped and completed a 120-second seek on its first check, but a repeat seek did not resume within 18 seconds. Deliberately blocking Apogee during a playing seek triggered a first-party fallback in 11.62 seconds with no page errors or same-provider refresh. VixSrc was selected, but that live replacement failed to decode and the next fallback returned 503. This is evidence of bounded recovery and remaining provider unreliability, not successful live continuation through every fallback.

Validation passed all 138 shared UI tests, 38 Watch/coordinator tests, UI/web type checks, and lint on changed code. Sanitized diagnostic evidence is stored in the companion JSON record; it excludes source URLs, signed parameters, member sessions, and raw control responses.

An additional four-scenario Playwright fixture run was attempted but its separate Next development server did not become ready; it was stopped before scenarios ran. This does not count as a browser-suite pass. The controlled progressive-loading comparison and deployed Watch checks above ran successfully as independent harnesses, with the recorded live-provider limitations. Temporary scripts and fixture processes were cleaned up.
