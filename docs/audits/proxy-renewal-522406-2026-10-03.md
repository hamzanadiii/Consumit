# Five-minute proxy renewal on movie 522406

The member reports recurring refresh/resume interruptions, roughly every five minutes, on movie 522406. A guest-session probe of the running stack returns relay source lifetimes of 295 seconds for Rive Zephyr, 290 for Storm Boron and 294 for Miami. Aggregate recent recovery metrics also show successful `reason=expired` relay refreshes; those metrics do not identify this individual session.

## Cause and regression

`accessDeadline` conservatively assigns unknown upstream expiry a five-minute source freshness deadline. Member playback previously used that deadline minus five seconds as the signed proxy capability expiry. The browser renews fifteen seconds beforehand and can retain the healthy old player attachment, but its old Worker segment capabilities still expire. Subsequent segment requests then force recovery and source attachment despite otherwise healthy media. This matches the reported cadence.

The API regression reproduces the hard cutoff: the estimated-expiry case returns 295,000 milliseconds where a bounded longer capability is expected. It fails before the correction and passes after it. Known-expiry, unmarked-source and direct-delivery cases retain the original authoritative deadline. SDK tests distinguish recognized URL/explicit expiry from the conservative estimate.

## Correction

Adapter-owned `expiryEstimated` metadata marks the distinction. The existing relay adapters use the shared source-access helper; static/unmarked sources remain conservative. Source validation and resolver cache freshness still use the original SDK deadline, but a member relay capability may use the existing thirty-minute maximum when expiry is estimated. Real upstream expiry remains authoritative and upstream servers still enforce their own access restrictions. The browser receives the signed capability's actual expiry. Admin diagnostic previews retain their short lifetime.

This is an API/SDK correction. The running API has been restarted; the existing Worker already supports and enforces the thirty-minute maximum, with no plan upgrade, policy expansion or new service. No player controls, progress ownership or provider settings change. Old grants cannot be extended; a new playback session or the next source renewal adopts the policy. Normal bounded renewals and real failure recovery remain; this does not promise gapless playback for an entire movie.

## Verification

Fresh guest sessions on the same movie return 1,800-second capabilities for Zephyr, Boron and Miami. In the actual shipped Consumit Player, an isolated Chromium session plays movie 522406 continuously through the deployed Zephyr relay for 330 wall-clock seconds at 3840×1920, decoding 7,925 frames. It records zero refresh/fallback requests, zero media HTTP failures, zero page errors and zero media-element reloads after startup. No time skipping is used. The diagnostic intercepts only initial source selection, progress/history writes and telemetry; real media responses are decoded. Automatic provider fallback is denied so another provider cannot produce a false pass.
